# ระบบแจ้งซ่อมหอพัก System A (Dormitory Maintenance Reporting System)

```
ผู้ดูแลออกรหัส 6 หลัก (แอป) → ผู้พักพิมพ์รหัสผูกห้อง (LINE) → แจ้งซ่อม (LINE) → ผู้ดูแลมอบหมาย (แอป) → ช่างเริ่มซ่อมและบันทึกผล (แอป)
→ ผู้ดูแลดูผลแล้วกดแจ้งผล → ผู้พักได้รับข้อความ LINE
```

ใช้ Supabase แผนฟรี (ฐานข้อมูล Postgres, Auth, Storage, Edge Functions) กับแอป Flutter สำหรับผู้ดูแลและช่าง

> สถานะ ณ 7 พ.ย. 2569
> - ฐานข้อมูลและ Edge Functions ทั้ง 5 ตัว deploy บนโปรเจกต์ Supabase `dorm-care` แล้ว เทสต์ฐานข้อมูลใน `supabase/tests` รันบน PostgreSQL ในเครื่องเท่านั้น
> - Edge Functions: เทสต์ตรรกะผ่าน 28 ข้อด้วย Node (`node --test`) ยังไม่เคยตรวจ type ด้วย Deno ในเครื่อง
> - แอป Flutter: build ผ่านบน GitHub Actions ทั้งเว็บและ APK เว็บเปิดที่ GitHub Pages
> - 6-7 พ.ย. 2569 ทีมทดสอบเส้นทางหลักบนระบบจริงครบ ตั้งแต่ล็อกอินด้วย OTP ผูกห้อง แจ้งซ่อม มอบหมาย บันทึกผลพร้อมรูป จนผู้พักได้ข้อความและรูปทาง LINE
>   ผลนี้ยังไม่ได้ลง SQA Checklist ต้องแนบภาพหน้าจอเป็นหลักฐานก่อน รายการอื่นใน Checklist ยังไม่ได้ทดสอบ

## โครงสร้าง

| ไฟล์ / โฟลเดอร์ | หน้าที่ |
| --- | --- |
| `supabase/migrations/…_init.sql` | ตาราง, RLS, ฟังก์ชันที่เปลี่ยนสถานะงาน, ผูกห้อง, OTP และเครื่องที่จำไว้ |
| `supabase/functions/line-webhook` | รับเหตุการณ์จาก LINE: ผูกห้อง แจ้งซ่อม ติดตามงาน |
| `supabase/functions/notify-resident` | ผู้ดูแลสั่งแจ้งผลทาง LINE (กันส่งซ้ำเมื่อกดลองใหม่) |

| `supabase/functions/password-reset-*` | ลืมรหัสผ่าน: ขอรหัสทางอีเมล แล้วตั้งรหัสผ่านใหม่ |
| `supabase/functions/_shared` | โค้ดที่ใช้ร่วมกัน (บทสนทนา LINE, ข้อความ, ตรรกะ OTP) เป็น JS ธรรมดา เทสต์ด้วย Node ได้ |
| `supabase/seed.example.sql` | ตัวอย่างใส่ห้อง พนักงาน และข้อความติดต่อ |
| `app/` | แอป Flutter |
| `scripts/` | สคริปต์ PowerShell สำหรับ deploy และรันแอปบน Windows |

## กติกาที่โค้ดบังคับ

งานซ่อม
- สถานะมี 3 ค่า: รอดำเนินการ (PENDING) → กำลังซ่อม (REPAIRING) → ซ่อมเสร็จแล้ว (COMPLETED)
- ช่างบันทึกผลแล้วงานเป็น "ซ่อมเสร็จแล้ว" ทันที แต่ระบบไม่ส่ง LINE เอง ผู้ดูแลต้องกด "แจ้งผลทาง LINE"
- ช่างเห็นและทำงานได้เฉพาะงานที่ได้รับมอบหมาย อัปโหลดรูปได้เฉพาะงานของตัวเองที่กำลังซ่อม
- ผู้พักเห็นเฉพาะงานของห้องตัวเอง
- รหัสผูกห้องใช้ได้ครั้งเดียว หมดอายุใน 3 วัน ฐานข้อมูลเก็บเฉพาะค่า Hash ใส่รหัสผิดได้ไม่เกิน 5 ครั้งต่อวัน (นับวันตามเวลาไทย)
- แจ้งซ่อมไม่สำเร็จ ข้อมูลที่ผู้พักกรอกยังอยู่ กด "ยืนยัน" ใหม่ได้โดยไม่เกิดใบงานซ้ำ
- ผู้ดูแลกดแจ้งผลแล้วเน็ตหลุด กดใหม่ได้โดยผู้พักไม่ได้ข้อความซ้ำ

การเข้าสู่ระบบของพนักงาน
- อีเมลและรหัสผ่าน แล้วต้องยืนยันรหัส OTP 6 หลักที่ส่งไปทางอีเมลทุกครั้ง
- ยืนยันแล้ว เครื่องนั้นไม่ต้องใช้ OTP อีก 30 วัน
- OTP ใช้ได้ 10 นาที ผิดได้ 5 ครั้ง ขอรหัสใหม่ได้ทุก 60 วินาที
- session ที่ยังไม่ผ่าน OTP อ่านหรือแก้ข้อมูลไม่ได้เลย (บังคับใน RLS ไม่ใช่แค่ที่หน้าจอ)
- บัญชีใหม่ต้องเปลี่ยนรหัสผ่านชั่วคราวก่อนใช้งาน รหัสผ่านยาวอย่างน้อย 8 ตัว
- ลืมรหัสผ่าน: กรอกอีเมล รับรหัสทางอีเมล ตั้งรหัสใหม่ แล้วทุกเครื่องถูกออกจากระบบและต้องยืนยัน OTP ใหม่
- เบอร์โทรเก็บไว้เป็นข้อมูลติดต่อเท่านั้น ส่ง OTP ทาง SMS ไม่ได้ เพราะ Supabase ต้องใช้ผู้ให้บริการ SMS ที่เสียเงิน

## ข้อจำกัดของแผนฟรีที่ต้องรู้

- โปรเจกต์ถูกพักอัตโนมัติถ้าไม่มีการใช้งาน 7 วัน ก่อนเดโมหรือส่งงานให้เข้า Dashboard แล้วกด Restore (ข้อมูลไม่หาย)
- แผนฟรีไม่มีการสำรองข้อมูลที่กู้คืนเองได้ ก่อนวันสำคัญให้ export ตารางสำคัญ (tickets, ticket_history, line_bindings, staff) เป็น CSV จาก Table Editor หรือใช้ `npx supabase db dump --data-only -f backup.sql` (คำสั่งนี้ต้องมี Docker)
- พื้นที่ฐานข้อมูล 500 MB, ไฟล์ 1 GB ระดับเดโมใช้ไม่ถึง

## ต้องเตรียมก่อน

1. คอมพิวเตอร์ Windows ที่ติดตั้ง Node.js 20 ขึ้นไป, Flutter 3.27 ขึ้นไป และ Android Studio
2. มือถือ Android สำหรับทดสอบ
3. บัญชี Gmail ของทีม 1 บัญชี สำหรับส่ง OTP (เปิด 2-Step Verification)
4. ช่อง LINE Messaging API ของบัญชี "Dorm Care แจ้งซ่อม"

## ขั้นที่ 1 สร้างโปรเจกต์ Supabase

1. https://supabase.com → New project ชื่อ `dorm-care` เลือก Region Singapore แผน Free จดรหัสผ่านฐานข้อมูลไว้
2. จด Project ref (ตัวอักษร 20 ตัวใน URL ของ Dashboard) ไว้ใช้ในขั้นที่ 3
3. Authentication → Sign In / Providers
   - ปิด **Allow new users to sign up** (พนักงานทุกคนสร้างโดยผู้ดูแลระบบ)
   - Email provider เปิดอยู่ ตั้ง Minimum password length = 8

## ขั้นที่ 2 สร้าง App Password ของ Gmail

1. ล็อกอิน Gmail ของทีม → https://myaccount.google.com/apppasswords
2. ตั้งชื่อ เช่น `dorm-care` แล้วกดสร้าง จะได้รหัส 16 ตัว ใช้ในขั้นที่ 3 (รหัสนี้แทนรหัสผ่าน Gmail อย่าส่งในแชตกลุ่ม)

ระบบส่งอีเมลผ่าน `smtp.gmail.com` พอร์ต 465 เพราะ Edge Functions ปิดพอร์ต 25 และ 587

## ขั้นที่ 3 Deploy

```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1 -ProjectRef <project ref>
```

สคริปต์จะรันเทสต์ ล็อกอิน Supabase สร้างตาราง ถามค่าลับ 4 ค่า (LINE secret, LINE token, อีเมล Gmail, App Password) แล้ว deploy ฟังก์ชันทั้ง 5 ตัว
ตอนจบจะแสดง Webhook URL สำหรับขั้นที่ 4

## ขั้นที่ 4 ตั้งค่า LINE

1. LINE Developers Console → ช่องของบัญชีนี้
   - คัดลอก Channel secret และออก Channel access token (long-lived) ไว้ใส่ในขั้นที่ 3
   - Webhook URL = URL จากขั้นที่ 3 → Verify → เปิด Use webhook
   - เปิด Webhook redelivery ถ้ามีให้เลือก
2. LINE OA Manager → การตอบกลับ → ปิดข้อความตอบกลับอัตโนมัติ
3. ปุ่ม Rich Menu ต้องส่งข้อความตรงตัว: `แจ้งซ่อม`, `ติดตามงาน`, `ผูกเลขห้อง`, `ติดต่อผู้ดูแล`

## ขั้นที่ 5 ใส่ข้อมูลตั้งต้น

1. Authentication → Users → Add user → Create new user: ใส่อีเมลและรหัสผ่านชั่วคราวของพนักงานแต่ละคน ติ๊ก Auto Confirm User
2. เปิด `supabase/seed.example.sql` แก้เลขห้อง ชื่อ อีเมล และบทบาทให้เป็นของจริง แล้ววางใน SQL Editor กด Run
3. ผลลัพธ์ด้านล่างต้องมีพนักงานครบทุกคน

## ขั้นที่ 6 รันแอป

```powershell
powershell -ExecutionPolicy Bypass -File scripts\app.ps1
```

ครั้งแรกสคริปต์จะถาม Project URL และ anon key (Project Settings → API) แล้วเก็บใน `app/supabase.json`
ถ้าไม่ใช้สคริปต์: `flutter run --dart-define-from-file=supabase.json`

## ยังไม่ได้ทำ / รอตัดสินใจ

- รหัสหมวดงาน (PLUMBING, ELECTRICAL, AIRCON, FURNITURE, OTHER) ตั้งตาม Prototype รอเทียบกับ RPT-05
- ข้อความ LINE อยู่ใน `supabase/functions/_shared/messages.js` และข้อความอีเมล OTP อยู่ใน `_shared/auth.js` รอทีมยืนยันถ้อยคำ
- ไม่มีหน้าจัดการพนักงานในแอป เพิ่มหรือปิดบัญชีผ่าน Dashboard และ SQL Editor
- ไม่ได้ทำตามขอบเขต: LINE LIFF, นัดหมายเข้าห้อง, EAC, Push Notification
- รูปหลังซ่อมที่ส่งทาง LINE เป็นลิงก์ชั่วคราว 30 วัน (`PHOTO_DAYS` ใน `_shared/notify.js`) หมดอายุแล้วรูปในแชตจะเปิดไม่ขึ้น
- System B (อุปกรณ์วัดน้ำ) เป็นผลิตภัณฑ์แยก ไม่อยู่ในโค้ดนี้
